## 二、八节点职责

| 节点 | 名称 | 输入 | 输出 | 核心逻辑 |
|------|------|------|------|----------|
| **LU** | 意图识别 | 用户问题 | `{intent_type, slots, confidence}` | 同义词预处理 → RAG检索 → LLM意图分类 → 置信度检查 |
| **SF** | 要素校验 | LUOutput | `{metric_code, dimensions, time_range, filters}` | 维度映射 → 时间解析 → 上下文继承 → 槽位补全 |
| **SQL** | SQL生成 | SFOutput | `{sql, sql_type, has_comparison}` | 策略选择：模板(简单) vs LLM(复杂) → RAG注入SQL示例 |
| **CK** | 纠错检查 | SQLOutput | `{sql, is_valid, corrected_sql}` | 规则引擎初筛 → 维度列名合法性 → LLM深度检查 |
| **EX** | SQL执行 | CKOutput | `{data, columns, row_count}` | 缓存查询(Redis 5分钟) → 异步HTTP请求StarRocks |
| **RV** | 结果验证 | EXOutput | `{is_valid, anomaly_flags, can_visualize}` | 空数据检测 → 极端值检测 → 缺失字段检测 |
| **CHART** | 可视化 | EXOutput+RVOutput | `{chart_type, echarts_config}` | 图表类型推荐 → ECharts配置生成 |
| **RS** | 报告生成 | RV+CHART+slots | `{answer, suggestions}` | 模板生成(简单) vs LLM生成(复杂) → 追问建议 |

## 三、LU 节点（意图识别）详细流程

### 3.1 完整流程图

```
用户问题
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 1: 文本预处理                                              │
│  - 去除多余空格，统一为单个空格                                    │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 2: 多轮对话上下文获取                                       │
│  - 从 Redis SessionStore 获取上一轮的 metric/time/dimensions      │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 3: 同义词预处理                                             │
│  - 从 business_terms 表加载同义词映射                             │
│  - 例："不含税收入" → "未税收入"                                  │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 4: RAG 指标检索                                            │
│  - 调用 MetricIndex.search_metric()                              │
│  - 检索最相关的 3 个指标（top_k=3）                               │
│  - 构建指标上下文：名称、代码、口径、维度、同义词                    │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 5: 构建 LLM Prompt                                         │
│  - 意图类型列表、时间转换规则、维度映射表                          │
│  - 指标上下文（RAG检索结果）、多轮上下文                           │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 6: 调用 LLM（腾讯云 DeepSeek）                              │
│  - temperature=0.7, max_tokens=4000                            │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 7: 解析 LLM 输出                                           │
│  - 提取 intent_type、confidence、slots、reasoning                 │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 8: 多轮继承（如果当前 slots 缺少 metric）                   │
│  - 继承上轮的 metric、metric_code、time_range、dimensions        │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 9: 置信度检查                                              │
│  - threshold = 0.7（从配置加载）                                 │
│  - confidence < 0.7 → 触发追问                                    │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 10: 记录历史到 SessionStore                                │
│  - Redis Key: llm_v1:session:{session_id}，TTL: 30分钟         │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
 LUOutput
```

### 3.2 意图类型定义

| 意图类型 | 说明 | 示例问题 |
|----------|------|----------|
| `query_value` | 查指标当前值 | "本月销售额是多少？" |
| `query_ranking` | 查排名/Top N | "销售额前10的店铺" |
| `query_trend` | 查趋势变化 | "近30天销售额趋势" |
| `compare` | 对比分析（同比/环比） | "本月vs上月销售额" |
| `query_dimension` | 查维度数据 | "各平台销售额" |
| `query_metadata` | 查业务/技术口径 | "销售额的业务口径是什么？" |
| `other` | 其他意图 | 无法识别时 |

### 3.3 Slots 输出完整结构

```python
slots = {
    # === 核心槽位 ===
    "metric": "销售额",              # 指标名称（中文）
    "metric_code": "MKI-02-0001",   # 指标代码

    # === 维度槽位 ===
    "dimensions": ["店铺", "平台"],  # 中文维度名列表
                                    # SF 节点转换为列名：{店铺: FSITE, 平台: PLATFORM}

    # === 时间槽位 ===
    "time_range": {
        "start": "2026-03-01",      # 具体开始日期
        "end": "2026-03-31",        # 具体结束日期
        "original": "本月",          # 原始表达
        # === 可选：对比时间（compare 意图时）===
        "compare_start": "2025-03-01",
        "compare_end": "2025-03-31",
    },

    # === 筛选槽位 ===
    "filters": [
        {"field": "PLATFORM", "op": "=", "value": "Amazon"},
    ],

    # === 聚合槽位 ===
    "aggregations": ["SUM"],         # 默认 SUM，可选 AVG/COUNT/MAX/MIN

    # === 操作槽位 ===
    "operations": [
        {"type": "order_by", "direction": "DESC"},
        {"type": "limit", "value": 10},
        {"type": "compare", "compare_type": "同比"},
        {"type": "percentage"},
    ],
}
```

## 四、SF 节点（要素校验）详细流程

### 4.1 完整流程图

```
LUOutput { intent_type, slots }
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 1: 获取指标信息                                            │
│  - 优先用 metric_code 精确匹配                                    │
│  - 否则用 metric_name 模糊匹配                                    │
│  - 获取 starrocks_sql、common_dimensions 等                      │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 2: 维度映射（铁律一）                                       │
│  - 将中文维度名转换为数据库列名                                     │
│  - {店铺: FSITE, 平台: PLATFORM, 三级品类: GROUP_3}            │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 3: 时间范围解析                                            │
│  - 解析 time_range.original → start/end                         │
│  - 支持：本月、上月、近7天、上周等                                 │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 4: 上下文继承（多轮对话）                                   │
│  - 如果当前 slots 缺少维度，从 context 继承                        │
│  - 如果当前 slots 缺少时间，从 context 继承                        │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 5: 槽位补全                                                │
│  - 如果 metric 有 common_dimensions，补全维度                      │
│  - 如果 time_range 只有 original没有具体日期，补全                 │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
 SFOutput { metric_code, starrocks_sql, dimensions, time_range, filters }
```

## 五、SQL 节点（SQL生成）详细流程

### 5.1 策略选择

```python
def _should_use_llm(sf_output) -> bool:
    """
    触发 LLM 的条件：
    1. 有衍生指标计算（同比/环比/占比）→ 用 LLM
    2. 有排序/限制操作（order_by/limit）→ 用 LLM
    3. 有维度分组（GROUP BY）→ 用 LLM
    4. 多维度组合（>2个维度）→ 用 LLM
    5. 有复杂筛选条件（>2个筛选）→ 用 LLM
    6. 其他情况 → 用 QueryBuilder 模板
    """
```

### 5.2 LLM 生成模式

```
SFOutput
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 1: 检索 SQL 示例（RAG）                                    │
│  - SQLExampleRetriever.retrieve()                               │
│  - 基于 metric_code、dimension、intent_type 检索                  │
│  - 返回 top_k=5 个 SQL 示例                                       │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 2: 扩展时间范围（如果需要对比）                              │
│  - 如果有 compare 操作，扩展 time_range                           │
│  - 同比：计算去年同期                                             │
│  - 环比：计算上一周期                                             │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 3: 构建 Prompt                                             │
│  - 槽位信息、维度映射表、SQL 示例                                  │
│  - 时间范围扩展说明（compare_requirement）                        │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 4: 调用 LLM                                                │
│  - temperature=0.7, max_tokens=4000                             │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────────┐
│  Step 5: 解析并补充 GROUP BY                                     │
│  - 解析 JSON 响应                                                │
│  - 如果 LLM 未生成 GROUP BY，尝试补充                             │
└─────────────────────────────────────────────────────────────────┘
    │
    ▼
 SQLOutput { sql, sql_type, has_comparison, has_percentage }
```

## 六、铁律规则

| 铁律 | 说明 | 实施节点 |
|------|------|----------|
| 铁律一 | 维度映射：中文维度名 → 数据库列名 | SF |
| 铁律二 | 指标匹配优先 exact match +40 分 | MetricClient |
| 铁律三 | GROUP BY/SELECT 中不能有中文列名 | CK |
| 铁律四 | 维度名反向映射：column_name → dimension_name（仅展示用） | RS/CHART |

## 九、配置管理

### 9.1 ConfigLoader

- **缓存时间**：1小时
- **强制刷新**：通过 `get_config(force_reload=True)`
- **配置来源**：PostgreSQL 数据库表

### 9.2 SessionStore

- **存储介质**：Redis
- **Key格式**：`llm_v1:session:{session_id}`
- **TTL**：30分钟
- **自动续期**：每次访问刷新TTL

## 十、数据流汇总

```
用户问题
    │
    ▼
LU ──► SF ──► SQL ──► CK ──► EX ──► RV ──► CHART ──► RS
```

### Slots 传递过程

| 节点 | 输入 slots | 输出 slots 变化 |
|------|------------|-----------------|
| LU | `{question}` | `{metric, time_range, dimensions}` |
| SF | `{metric, ...}` | `{metric_code, starrocks_sql, dimensions, time_range}` |
| SQL | `{metric_code, dimensions, ...}` | `{sql}` |
| CK | `{sql}` | `{corrected_sql}`（如有错误） |
| EX | `{sql}` | `{data, columns, row_count}` |
| RV | `{data}` | `{is_valid, anomaly_flags, can_visualize}` |
| CHART | `{data, columns}` | `{chart_type, echarts_config}` |
| RS | `{data, slots}` | `{answer, suggestions}` |
